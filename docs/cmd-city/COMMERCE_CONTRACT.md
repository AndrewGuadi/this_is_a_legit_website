# CMD City local goods and freight contract — CMD-05 foundation

Direct Codex standalone implementation. Integration into core/save/households/region is a separate required step; a module alone is not a delivered game feature or verified SimCity equivalent.

## Stock ownership and identity

`city.inventory.goods` remains the one central warehouse quantity. Commerce owns `producerStock[N]`, `retailStock[N]`, `looseGoods`, and actual vehicle cargo. Goods can occupy exactly one owner at a time.

`openingGoods + produced + externalIn = warehouse + producers + retail + loose + cargo + consumed + externalOut`.

Opening migration records the existing warehouse once and creates zero producer/retail stock and zero trucks. It does not fabricate historical deliveries, refresh inventory or invent money. An optional future opening partition would have to debit this same warehouse and document its conservation; this module does not perform it.

## Stable schema and bounds

Commerce schema1 contains exactly `version,lastMonth,nextId,producerStock,retailStock,looseGoods,vehicles,roadLoad,counters`.

- City dimensions: positive integers with at most1280tiles.
- Each producer/retail stock: integer0–1,000,000. Warehouse retains its existing0–1,000,000 bound. Loose recovered goods:0–1e12.
- At most32saved freight vehicles, each payload0–100, at most1280orthogonally contiguous path nodes; IDs positive unique integers below `nextId`, bounded1e12. Empty paths represent waiting and have cursor0. Historical paths may contain newly blocked tiles, but movement never traverses them until they are legal again.
- Vehicle keys: `id,source,origin,target,destination,position,status,path,cursor,payload`. Sources: producer/warehouse. Status: outbound/returning. Outbound destination equals its shop target; returning destinations are the original producer or the regional gateway. Warehouse-origin trucks originate at the gateway.
- Integer cumulative counters0–1e15: `openingGoods,produced,externalIn,externalOut,consumed,delivered,returned,completedTrips,salvaged`. Delivered/returned/salvaged describe internal movement and are not extra material sources.
- Saved road loads are bounded nonnegative integers; exact city/region byte guards remain authoritative. Entity caps do not promise every combined save fits.

Strict validation checks keys/types, quantities, clocks, stock ownership, vehicle/path/cursor/destination consistency, ID uniqueness and exact material identity. Scalar overflow rejects before mutation. Monthly processing works on a detached candidate and commits only after successful validation.

## API

- `createCommerce(city)`: pure initial schema1 with opening warehouse quantity and `lastMonth=city.month`.
- `validateCommerce(state,city,{stable=true})`: stable marker equals `city.month`; processing validation permits `city.month+1` as well. Throws on invalid state.
- `advanceCommerce(city,metrics)`: current month transaction, target marker `city.month+1`; repeated target calls are inert. Produces actual staffed industrial goods into producer stock, then routes real freight. Commits candidate commerce and warehouse together. Returns report plus `changed`.
- `commerceReport(city)`: pure defensive snapshot of warehouse/local/cargo stock, counters, vehicles and last-assigned road loads; reports exact conservation.
- `commerceRetailStock(city,index)`: bounded read of a shop's physically delivered inventory.
- `consumeRetail(city,index,quantity)`: transfers up to requested available shop goods to cumulative consumed; returns actual count. Household callers perform their existing reachable/staffed/utility/wallet checks and charge only actual count. Closed/burning/non-retail sites cannot sell. No municipal/private money is generated by this hook.
- `transferWarehouse(city,signedQuantity)`: authoritative trade/regional/project integration hook; positive inflows debit the external source and negative outflows credit it in their caller's existing transaction. This hook adjusts warehouse and externalIn/out by the actual bounded transfer and returns that signed count. It is not a player-facing free-goods action.
- `preserveCommerceDemolition(city,index)`: before replacing a lot, conserves its producer/retail stock into loose recovered goods and marks targeting deliveries for return. Returns an action result, with no partial mutation on refusal.
- `commerceAction(city,{type:"recallFreight",id})`: recalls an existing outbound vehicle. It returns over actual roads with cargo; it never teleports inventory.

## Integration order

1. Create/migrate commerce exactly once. Extend whole-city strict schema and legacy handling explicitly.
2. Replace current direct industrial `inventory.goods += floor(jobFill*.8)` with commerce's producer production; do not execute both.
3. Replace every goods trade import/export, regional shipment send/arrival and project contribution warehouse mutation with `transferWarehouse`, inside existing economic/region transactions. Other resources remain unchanged.
4. After actual production inputs/trade and before household shopping, call `advanceCommerce` with current operating access, actual job filling, utilities and commuter road loads. The function owns industrial goods production and never resets inventories.
5. Replace household global-goods shopping loops with per-shop `commerceRetailStock`/`consumeRetail` and preserve actual wallet/tax bookings. Subtract freight road-load reservations when calculating remaining shopping capacity. Existing commercial shrink/warning checks must use local retail availability rather than the central warehouse.
6. Household and commerce future-clock markers become stable when core increments the city month. Any later transaction failure must roll back the complete city/region, including commerce, goods and wallets.
7. All demolitions, burnouts and disasters call preservation before overwriting lots. Save imports validate complete material identity; no silent correction of malformed saves.

## Operating and routing contract

Metrics require arrays of actual `jobFill`, `operationAccess` (or access), road loads and power/water ratios. Optional `retailCapacityByTile[N]` is actual staffed monthly retail throughput for tower shops, not a stock quantity. Commercial default throughput is floor(jobFill×4); stock target is twice throughput, capped at1,000,000, and monthly unloading is bounded by throughput. Reduced capacity retains existing stock.

Producer goods originate at their actual industry frontage. Warehouse and loose recovered goods originate at the protected regional gateway. Warehouse dispatch capacity is finite, increased by working trade facilities; producers have finite active truck slots. Total saved freight is at most32trucks with100goods each. Shop admission rotates deterministically with month to avoid permanent first-index preference.

Routes use active gateway-connected roads/avenues/bridges. Trips move at most16road edges per game month; each crossed undirected shared edge reserves one truck equivalent against actual commuter road use and other trucks. A blocked path/closed destination does not lose cargo. Deliveries unload only on arrival at an operating shop with receiving room/budget. Empty trucks return physically before their slot becomes reusable; recalled/undeliverable cargo returns to an operating producer or the gateway. Cargo that cannot route waits in its saved vehicle. Recovered demolition stock remains explicit loose stock, not an invented delivery.

All numerical balancing is original. This is not a complete firm payroll, named-driver, traffic-lane, external-market, vehicle-timetable or reference-equivalence claim.

## Implementation boundaries before integration

The current foundation routes producer-to-shop and central-warehouse/gateway-to-shop deliveries. Normal producer-to-export-depot cargo is not implemented yet; only central warehouse goods are available for existing trade exports. Loading/unloading remains discrete monthly activity, not continuous vehicle or firm simulation. Scalar consumption/warehouse hooks check their affected values and overflow before mutation; their caller must start from a validated state and retain the whole-city/region transaction boundary. Full `validateCommerce` remains the strict material/shape check.
