# Visual Accessibility

Use the existing arcade identity and original assets. Render all states, not just the happy path. Keep full playfield visible without stretched physics, readable HUD and reachable controls in portrait/landscape. Use HTML buttons/instructions outside canvas with visible keyboard focus and understandable labels. Test contrast and non-color-only state signals; respect reduced motion. Run automated accessibility checks, then manual keyboard/focus and visual checks. Inspect screenshots from actual runs and name their sizes/browser. Document limits of nonvisual canvas play. No fake screenshots or unsupported AAA/accessibility claims.
